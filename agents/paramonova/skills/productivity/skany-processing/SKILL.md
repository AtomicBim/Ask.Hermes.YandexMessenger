# Обработка сканов (папка СКАНЫ)

Периодическая задача: разобрать сканы из почтовой папки «СКАНЫ», распознать каждый, переименовать по «Сценарию 1», сформировать архивы по дням и отправить на почту.

## When to use

Пользователь просит «провести анализ папки СКАНЫ», «распознать сканы», «переименовать по сценарию», «сформировать архив по дням», «отправить на почту».

## Где лежат сканы

- «СКАНЫ» — это папка в почте (IMAP), НЕ файловая папка и НЕ Яндекс.Диск. Modified UTF-7 имя: `&BCEEGgQQBB0EKw-`.
- Каждый скан — PDF-вложение с именем `docNNNNNNYYYYMMDDHHMMSS.pdf`. Дата скана = `YYYYMMDD` в имени файла (regex `2026\d{4}`), а НЕ дата письма (заголовок `Date`).
- Подключаться к IMAP только по IPv4 `77.88.21.125:993` (IPv6 периодически падает).

## Workflow

1. **Скачать PDF** из папки СКАНЫ: `SEARCH (SINCE "1-Oct-2026" BEFORE "1-Nov-2026")`, затем `BODY.PEEK[]` и вытащить вложения из MIME-дерева (`part.get_filename()` + `get_payload(decode=True)`).
2. **Конвертировать первую страницу в PNG** через pymupdf (dpi 150) — у сканов нет текстового слоя.
3. **Распознать каждую страницу через vision** (`vision_analyze`), либо распараллелить через `delegate_task` (до 8 изображений на подзадачу, параметр `images`). Подзадачи возвращают структурированные реквизиты (тип/номер/дата/контрагент/сумма/содержание), а переименование делать централизованно по правилам ниже.
4. **Переименовать** по правилам Сценария 1.
5. **Сгруппировать по дате скана** (из имени файла) и сформировать отдельный zip-архив на каждый день: `СКАНЫ от ДД.ММ.ГГГГ.zip`.
6. **Отправить архивы на почту** через SMTP (см. скилл imap-mail-search, раздел про отправку).

## Сценарий 1 — правила наименования (всегда)

1. Входящее письмо в адрес АО «Корпорация «Атомстройкомплекс»: `2026-11-03 ЭкоХим 1336 направление ОЛ актуального` (дата + отправитель + номер + содержание).
2. Исходящее письмо от АО «Корпорация «Атомстройкомплекс»: `2026-11-13 АдмСысерти 01-003_26-3504 отчет 45`.
3. Сопроводительное на раздел рабочей документации: `2026-11-11 ЭкоХим 1380 сопровод КМ 13,15`.
4. Протокол совещания по Сысерти: `44. Протокол совещания 44 от 05.11.2026`.
5. Договор: `ЭкоХим Договор подряда №475_26 от 30.01.2026` (юр.лицо-контрагент).
6. Дополнительное соглашение: `ДС9 от 27.08.2026 ЭкоХим`.
7. Документы закрытия (КС-2): `КС2 №1 от 19.06.2026 на 125 786,51 РДРСУ` (юр.лицо — не Атомстройкомплекс).
8. Счет-фактура: `СФ 26 от 13.07.2026`.
9. Счет: `Счет 11 от 17.06.2026`.
10. Накладная / акт приема-передачи документации: `№37 от 27.10.2026 15 КМ,АР изм. 1`.
11. Символ `/` в наименовании заменять на `_`.

## Pitfalls

- **pymupdf живёт в отдельном venv** `/opt/data/environments/pdf-pymupdf/<gen-...>/venv/bin/python`, а не в venv Hermes — использовать его для конвертации PDF→PNG.
- **У сканов нет текстового слоя** (`get_text()` возвращает пустую строку) — распознавать только через vision, не через извлечение текста.
- **Дата скана — в имени файла, а не в `Date` письма**; группировать архивы по дате из имени файла, иначе письма за один день разъедутся по датам отправки.
- **SMTP — по hostname `smtp.yandex.ru`, не по IP** (иначе TLS-сертификат не валиден); IMAP терпит IP, SMTP — нет.
- **App-password** в `~/.config/mail/atomsk` (chmod 600), login `paramonova@atomsk.ru`.
- **50+ сканов распараллеливать** через `delegate_task` (до 8 изображений на подзадачу), иначе последовательный vision-OCR займёт десятки вызовов и зальёт контекст.
- **Лимит письма Яндекса ~25 МБ** (с учётом base64 ~33% накладных). Если суммарный размер архивов > ~18 МБ, разбивать на несколько писем (жадная группировка по ~18 МБ сырого веса) — иначе SMTP вернёт `552 5.3.4 message file too big`.
